# 手机竖屏近景构图实施计划

> 使用 writing-plans 制订、executing-plans 逐项执行，单代理。用户已确认：允许裁掉部分树冠，优先让树显得大。沿用当前未提交工作区，不改造型、不自动提交或推送。

**目标：** 修正竖屏成树阶段体量过小的问题，重新交付 15 秒、1080×1920 的 MP4。

**架构：** 仅修改 `app/src/timeline.ts` 的竖屏镜头轨迹，网页竖屏预览与视频导出共用该轨迹。0–4 秒近景和所有生长时序保持不变；4–10 秒平滑过渡到较近中景；10 秒后保持主体高度约占画面六至八成，允许左右冠缘出画，末尾不拉远。横屏镜头、默认造型研究、模型尺寸与灯光不变。

**技术栈：** Three.js / TypeScript / Vitest、既有本地逐帧导出器、FFmpeg / FFprobe、Chrome DevTools MCP。

## 取舍

1. **采用：移动相机靠近并保留 48° 视场角。** 让树干、枝叶层次和圆片细节更清楚，主动裁切两侧树冠。
2. 只放大旧视频：会损失像素细节且无法优化视角，不采用。
3. 继续保留完整宽冠：无法解决用户反馈的主体过小，不采用。
